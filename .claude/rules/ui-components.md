# UI components

- Check `src/components/ui/` before writing a primitive; add missing ones with `npx shadcn@latest add <name>`.
- `src/components/ui/` is shadcn/ui code owned by the project: keep its API, map colours to tokens, never use `transition-all`.
- Feature components go in `src/components/<feature>/` and compose the primitives.
- Semantic tokens only (`bg-primary`, `text-muted-foreground`). No raw palette classes, no bracketed colour/spacing values.
- No `dark:` chains: theming happens in `src/index.css` through `:root` / `.dark` custom properties.
- No outer margins on components; accept a `className` prop and merge it last with `cn()`.
- State through attributes (`data-state`, `aria-*`, `:disabled`), not extra classes.
- Every interactive element is keyboard accessible with a visible `:focus-visible` style; status is never conveyed by colour alone.
- Every exported component has a JSDoc block and a named, exported `XProps` type. Exception: primitives generated by the shadcn CLI in `src/components/ui/` keep their upstream API so they can be updated; wrap them in a feature component instead of rewriting them.
