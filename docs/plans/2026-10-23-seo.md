## Summary

Give the app a real document title and the metadata link-preview crawlers read. `index.html` gets the site name, a description, text-only Open Graph / Twitter Card tags and `theme-color`. Every page sets its own `<title>` through React 19's built-in `<title>` hoisting, and the exceptions inbox gets a screen-reader-only `h1`. Indexing, canonical URLs, performance and HTTP status codes stay out of scope.

## Steps

1. **Static metadata** — `index.html`
   - `<title>Shipment visibility</title>`.
   - `<meta name="description">` with the agreed description.
   - Open Graph: `og:type` = `website`, `og:site_name`, `og:title` = "Shipment visibility", `og:description`, `og:locale` = `en`. No `og:url` or `og:image`.
   - Twitter: `twitter:card` = `summary`, `twitter:title`, `twitter:description`.
   - `<meta name="theme-color">` twice, with `media="(prefers-color-scheme: light)"` / `dark` and the hex values above (comment their token origin).
   - These are static because preview crawlers do not run JavaScript; copy is duplicated from `src/locales/en.ts` by necessity.
2. **Messages** — `src/locales/en.ts`
   - `documentTitle.page`: `'{page} · Shipment visibility'`.
   - No new heading message: the exceptions `h1` and title reuse `opsExceptions.title` ("Exceptions inbox").
3. **`DocumentTitle` component** — `src/components/layout/DocumentTitle.tsx`
   - `export type DocumentTitleProps = { page: string }`; renders `<title>{intl.formatMessage({ id: 'documentTitle.page' }, { page })}</title>` (a single string child, as React requires).
   - JSDoc explains the hoisting, the static fallback in `index.html`, and that a page must render exactly one at a time.
4. **Titles per page** — one `DocumentTitle` per rendered state, never two at once:
   - `src/pages/ops/OpsExceptionsPage.tsx`: the shipment id when `shipmentId` is set, otherwise `opsExceptions.title`.
   - `src/pages/ops/OpsShipmentsPage.tsx`: `opsShipments.title`.
   - `src/pages/ops/OpsShipmentPage.tsx`: the shipment id from the URL.
   - `src/pages/customers/CustomerShipmentsPage.tsx`: inside `PageMain`, `customerShipments.title`.
   - `src/pages/customers/CustomerShipmentPage.tsx`: inside `DetailLayout` (the `notFound` branch renders `NotFoundPage`, which brings its own title).
   - `src/pages/NotFoundPage.tsx`: `notFound.title` (covers the catch-all route and the unknown customer / shipment branches of `CustomerGate` and `CustomerShipmentPage`).
5. **Screen-reader `h1` on the exceptions inbox** — `src/pages/ops/OpsExceptionsPage.tsx`
   - `<h1 className="sr-only">` with `opsExceptions.title`, rendered only in the branches where no exception is open (desktop with the empty state, narrow inbox). Visible layout unchanged.
6. **Docs** — `docs/implementation/2026-10-23-seo.md`
   - Implementation log with progress and any deviation.

## Acceptance criteria

- [ ] Viewing the page source of any route shows `<title>Shipment visibility</title>`, the meta description, the Open Graph and Twitter tags and the two `theme-color` metas; there is no `og:image`, `og:url` or canonical link.
- [ ] The browser tab reads "Exceptions inbox · Shipment visibility" on `/ops/exceptions`, "All shipments · Shipment visibility" on `/ops/shipments`, "Your shipments · Shipment visibility" on a customer list.
- [ ] Opening a shipment (ops detail, exception detail or customer detail) changes the tab to "SH-1042 · Shipment visibility" for SH-1042; going back restores the list title.
- [ ] An unknown path, an unknown customer and another customer's shipment read "Page not found · Shipment visibility".
- [ ] Only one `<title>` rendered by React exists in `<head>` at any time.
- [ ] On `/ops/exceptions` with no exception open, a screen reader finds one `h1` "Exceptions inbox"; it is not visible. With an exception open, the only `h1` is the shipment title.
- [ ] `npm run build`, `npm run lint`, `npm run test` and `npm run test:e2e` pass.

## Test strategy

## Out of scope

- Indexing policy, `robots.txt`, `sitemap.xml`, canonical links and `og:url` (user: indexing left out, so no production domain or `VITE_SITE_URL`).
- Preview image, product favicon, `apple-touch-icon`, web manifest (user: text-only previews).
- Route-level code splitting and font subsets (user: left out for now).
- Real HTTP 404 status codes and `noindex` on the 404 page (user: not touched).
- Prerendering / SSR (ADR 0001: Vite SPA only).
- New automated tests (user decision).
